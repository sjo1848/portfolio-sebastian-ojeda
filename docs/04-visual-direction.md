# Dirección visual

## Objetivo

Transmitir ingeniería sólida, claridad, criterio y capacidad de entrega sin caer en una estética genérica de “programador hacker”.

## Principios

- Jerarquía clara.
- Alto contraste.
- Lectura rápida.
- Espacio suficiente.
- Evidencia visual real.
- Movimiento limitado y funcional.
- Mobile-first.
- Accesibilidad.

## Dirección recomendada

- Fondo claro predominante.
- Secciones oscuras puntuales.
- Un color de acento.
- Tipografía sans serif profesional.
- Monoespaciada únicamente para detalles técnicos.
- Tarjetas amplias.
- Diagramas limpios.
- Capturas reales.

## Evitar

- Fondo de terminal en todo el sitio.
- Texto mecanografiado.
- Nubes de logos.
- Barras porcentuales de habilidades.
- Animaciones constantes.
- Efectos 3D innecesarios.
- Gradientes excesivos.
- Frases grandilocuentes.
- Más de dos CTA principales por sección.

## Componentes iniciales

- Header.
- Hero.
- ProjectCard.
- CapabilityGroup.
- ProcessStep.
- ExperienceItem.
- ContactPanel.
- Footer.
- CaseStudySection.
- StatusTable.
- ArchitectureDiagram.

## Estados

Todos los componentes interactivos deben incluir:

- Default.
- Hover.
- Focus visible.
- Active.
- Disabled, cuando corresponda.

## Responsive

Puntos a validar:

- 360 px.
- 768 px.
- 1024 px.
- 1440 px.

## Fotografía

Dos opciones válidas:

### Con retrato

Fotografía profesional, simple, fondo limpio y encuadre natural.

### Sin retrato

Identidad basada en nombre, tipografía, diagramas y capturas.

No usar avatares generados como sustituto de una fotografía profesional.
