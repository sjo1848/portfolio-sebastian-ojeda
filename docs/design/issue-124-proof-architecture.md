## 3. Exact provenance contract

Every recruiter-facing proof item must carry:

| Field | Requirement |
|---|---|
| Source repository | Canonical upstream URL. |
| Source commit | Exact immutable source commit that produced the capture. Unknown stays unknown; do not infer from copy commit or nearby HEAD. |
| Capture run | Workflow/run ID or local manifest binding command, browser, fixture seed, output path and SHA-256. |
| Data classification | Explicit authorized synthetic/test fixture or other evidenced class; never infer synthetic from a screenshot or email suffix alone. |
| Environment | Exactly local runtime, controlled staging, or production, as evidenced. Current HMS captures are local runtime. |
| Artifact identity | Portfolio path, dimensions, SHA-256; upstream path/hash where available. |
| Proves / does not prove | Narrow visible behavior, plus explicit exclusions such as Product Acceptance, production release, uptime, live availability, unshown authorization, and unrecorded transitions. |
| Limitation | Local/synthetic context and relevant external gates in adjacent localized copy. |

## 4. Future HMS walkthrough architecture — mode B

Future local recording contract only. It is not authorization to capture or publish now.

| Concern | Contract |
|---|---|
| Recording source | Actual HMS web app running in its documented local Worker/D1 runtime, from the external project's approved candidate, only after CF-UX-MOBILE-001 and required external Controller/Product Owner gates. No remote staging session. |
| Required scenes | One genuine reception action from known fixture state through visible result; one real cross-tenant request denied by the running application. Do not fabricate an overlay or imply a test result that did not occur. |
| Fixtures | Deterministic authorized synthetic fixtures; record seed/reset identifier. No real hotel, guest, payment or employee data. |
| Credentials | No secrets, tokens, passwords, real email addresses, password-manager UI or auth headers visible/included. Use only local synthetic profile if runtime requires authentication. |
| Endpoint | Local capture only. No public writable endpoint, public admin UI, persistent service, intermediate deployment or new staging. |
| Duration | Target 60–90 seconds, limited to the two scenes and a provenance/limitations end card. No autoplay. |
| Reset/reproduction | Start with documented clean local reset; record exact runbook commands, browser/version, approved candidate SHA, seed, output path and hashes in capture manifest. Reproduce the same semantic outcomes on a second run even if timestamps differ. |
| Output/fallback | Static video plus captions/transcript and adjacent EN/ES limits. Preserve ordinary images and case study if video fails or JavaScript is disabled. |
| Cost | Static artifact playback only; no recurring hosting, scheduled runtime, exposed DB, credential service, analytics or monitoring dependency. |
| Gate | No capture/publication until external gates complete and a new Controller authorization explicitly opens the walkthrough increment. |

Label if later approved: “Local recorded walkthrough · synthetic test data” / “Walkthrough local grabado · datos sintéticos”. Never call it live, production, accepted, or a public demo.
