# Branding — Independent Critic — Discovery

Issue: #63
Reviewed artifact: `docs/branding/01-discovery.md`
Role: Independent Critic / Verifier

## Verdict

**PASS WITH CONDITIONS**

Discovery is sufficient to continue to DEFINITION, but the next phase must resolve the conditions below before any visual direction can be treated as approved.

## What is strong

1. **The reference set is used as evidence, not as templates.** The artifact extracts patterns instead of proposing direct visual imitation.
2. **Recruiter readability is protected.** It does not discard the current Full-Stack positioning simply to create a more unusual brand.
3. **Evidence remains the credibility mechanism.** The document correctly avoids replacing screenshots, case studies and verified implementation with brand language.
4. **The core tension is correctly identified:** a generic job title helps categorization, while a memorable proposition is needed for differentiation.
5. **The current palette is treated as an asset to evaluate rather than something to replace by fashion.**
6. **The portfolio’s method is recognized as differentiating evidence but not promoted above the work itself.**

## Findings / conditions

### C1 — Reference sample bias
Four developer portfolios are not sufficient evidence for universal visual rules. DEFINITION must treat their shared patterns as directional, not normative. The brand should remain anchored in Sebastián’s actual projects and professional objective.

### C2 — Audience hierarchy must be explicit
The artifact names recruiters, clients and technical peers, but does not rank them. DEFINITION must name a primary audience and define what that audience needs to understand first.

### C3 — Conversion objective must be explicit
Branding is not successful merely when the site is more memorable. DEFINITION must identify the desired actions: understand role, inspect selected work, open a case study, contact Sebastián / inspect GitHub.

### C4 — “Operational” can become too narrow
The operational-systems lens is evidence-backed, but if promoted as the formal role it could unnecessarily exclude standard Full-Stack / Backend searches. DEFINITION should use it as differentiation beneath the role anchor unless stronger evidence supports changing the category.

### C5 — Mountain/Cuyo motifs are high-risk
They may create authentic regional character, but literal peaks, contour maps, mining imagery or outdoors branding could misclassify the portfolio. Any regional influence must remain abstract and secondary.

### C6 — Metadata density needs a measurable rule
The critique of project-card density is correct but vague. DESIGN should define what information must remain visible on cards and what moves to case studies.

### C7 — Brand success needs observable criteria
Before DESIGN, DEFINITION should specify acceptance checks such as:
- role recognizable in the first viewport;
- differentiator expressible in one sentence;
- primary projects visually dominate supporting sections;
- CTA hierarchy is unambiguous;
- no section looks like a generic component-library demo;
- ES/EN preserve equivalent identity;
- accessibility/performance do not regress.

## Risk register

| Risk | Severity | Mitigation |
| --- | --- | --- |
| Branding hides recruiter keywords | High | Keep role anchor explicit |
| Visual identity becomes mountain/mining cliché | Medium-high | Abstract motifs only; critic review |
| Too many decorative UI tokens increase noise | Medium | Fewer recurring devices, stronger hierarchy |
| Copy becomes grandiose relative to evidence | High | Claims must map to case-study proof |
| Inspiration turns into imitation | Medium-high | No copied naming system, layouts or signature vocabulary |
| Brand work delays project evidence | Medium | Branding scope limited to system-level changes |

## Exit decision

Discovery may proceed to **DEFINITION** if C1–C7 are incorporated into the brand contract.

No BUILD is authorized.
